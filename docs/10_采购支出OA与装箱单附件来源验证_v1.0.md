# 采购支出 OA 与装箱单附件来源验证 V1.0

更新时间：2026-07-14

## 1. 这份文档的用途

这份文档只做一件事：

把 2026-07-14 当天从真实钉钉审批页里核到的字段来源结论单独记下来，方便后续开发时直接判断：

1. 哪些字段可以从 `国际物流 OA` 取
2. 哪些字段要从 `采购支出 OA` 取
3. 哪些字段必须从 `钉钉附件中的装箱单 / Packing List` 解析

## 3. 国际物流 OA 实际核到的字段

### 3.1 国际物流 OA 可直接看到的基础字段

本次在国际物流审批页中，实际能看到以下字段或等价字段：

1. `物料编码`
2. `物料名称（中文）`
3. `物料名称（西语）`
4. `规格型号`
5. `数量`
6. `单位`
7. `收件人`

这些字段适合作为：

`批次创建时的第一轮物料主清单来源`

### 3.2 国际物流 OA 可直接看到的物流维度字段

本次实际能看到或确认存在：

1. `物流方式`
2. `目的地`
3. `重量`
4. `预计发货日期 / 节点时间`

但这里要特别注意：

国际物流 OA 页面的重量、数量信息不应直接视为最终核算口径，后续仍要以实际装箱单和人工修正为准。

### 3.3 国际物流 OA 实际存在附件区

本次附件区实际看到：

1. `7月份燃油附加费.png`
2. `2026.7.3DHL快递清单.xlsx`

这说明：

系统后续不能只拉审批表单字段，还必须把钉钉审批附件一起纳入解析链路。

### 3.4 国际物流 OA 实际存在关联审批区

本次在“关联审批单 Asocar órdenes de compra”中，实际看到多张采购支出审批单，例如：

1. `黄丽瑶提交的采购支出 Gastos de compra`

这说明：

## 4. 采购支出 OA 实际核到的字段

### 4.1 已确认可以从采购支出 OA 获取的字段

基于已打开的真实采购支出审批页，当前可以明确：

1. `采购单价`：有行级 `单价Precio`
2. `采购数量`：有行级 `数量Cantidad`
3. `采购金额 / 总货值来源`：有行级 `总金额Monto Total`
4. `采购币种`：页面中存在 `币种Moneda`
5. `物料编码`：有行级 `物品编码Código`
6. `规格型号`：有行级 `物品规格Especificacion`

因此当前结论是：

`C 单价 / E 总货值 / 采购币种` 这几类字段，不应该从国际物流 OA 里硬凑，而应该正式从 `采购支出 OA` 补。

### 4.2 采购支出 OA 的典型业务含义

采购支出 OA 更适合作为：

1. `采购价格来源`
2. `采购币种来源`
3. `货值来源`
4. `采购原单追溯来源`

而不是：

1. 发货重量来源
2. 发货体积来源
3. 最终清关杂费来源

---

## 5. 装箱单附件需要承担的字段来源

结合同事口径和附件实际情况，当前可以明确：

以下字段不能只靠 OA 表单本身：

1. `实际发货数量`
2. `毛重 KG`
3. `体积 m3`
4. `体积重 KG`
5. `计费重 KG`

这些字段更适合来自：

`钉钉审批附件中的装箱单 / Packing List / 装柜表`

并且需要支持：

1. 多模板识别
2. 多 sheet 识别
3. 人工修正
4. 修正留痕

---

## 6. 当前可以落地的字段来源结论

### 6.1 第一层：国际物流 OA

适合承接：

1. 批次头
2. 审批追溯
3. 物流基础字段
4. 第一轮物料明细
5. 附件入口
6. 关联采购支出入口

### 6.2 第二层：采购支出 OA

适合承接：

1. 采购单价
2. 采购币种
3. 总货值来源
4. 采购审批单追溯

### 6.3 第三层：钉钉附件装箱单

适合承接：

1. 实际发货数量
2. 毛重
3. 体积
4. 体积重
5. 计费重

## 7. 对当前后端开发的直接影响

基于这次真实页面核验，后端一期至少要有两个正式入口：

1. `import_purchase_expense_oa`
   用来补采购单价、采购币种、总货值来源、采购原单追溯

2. `parse_packing_list_attachment`
   用来解析装箱单附件，补实际发货数量、重量、体积类字段

同时 `Overseas Cost Item` 建议正式补这些字段：

1. `product_name_es`
2. `spec_model`
3. `unit`
4. `recipient`
5. `purchase_currency`
6. `actual_shipped_qty`
7. `volume_m3`
8. `volume_weight_kg`
9. `chargeable_weight_kg`
10. `source_type`
11. `source_doc_no`
12. `source_file_name`
13. `source_attachment_id`
14. `parse_status`
15. `manual_override_flag`
16. `manual_override_reason`
17. `dingtalk_instance_id`
18. `dingtalk_official_url`

## 8. 还没最终确认、但必须继续问清楚的点

1. 多张采购支出审批同时关联一票物流时，最终按什么规则汇总回物料行
2. `采购支出 OA` 里哪个字段是最终正式的采购币种口径
3. 装箱单解析后，`quantity` 是直接覆盖为实际发货数量，还是单独保留 `actual_shipped_qty`
4. 海运一期是否现在就正式启用 `体积 / 体积重 / 计费重`
5. 海关进口名称、海关分类编码最终以主数据、报关资料还是完税资料为准

一句话结论：

`国际物流 OA 负责起批次和挂来源，采购支出 OA 负责补价格，钉钉附件装箱单负责补真实发货物理数据，这三层都要接，不能只接其中一张表。`
