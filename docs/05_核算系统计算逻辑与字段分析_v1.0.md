# 海外采购综合成本核算系统技术方案 V0.2

## 1. 目标与范围

本方案面向“海外采购综合成本核算”场景，目标是在现有进销存升级版 ERP 的基础上，新增一套成本核算模块，替代财务手工维护 Excel 的方式，实现从采购、国际物流、清关、入库到 ERP 批次成本回写的闭环。

已确认前提：

1. 现有 ERP 已支持批次成本和 FIFO。
2. 一个物流批次可能对应多个采购单、多个供应商、多个币种。
3. 分摊规则主要按货值、重量、体积执行。
4. 支持先暂估、后补差。
5. 财务允许修改 AI/系统识别结果，但必须保留修改痕迹。
6. 当前希望输出的是给开发落地的技术方案版本。

建议实施边界：

1. 一期先只做墨西哥海运主场景。
2. 一期先做“可复核、可追溯、可回写”的 MVP，不追求全自动无人工。
3. 空运、快递、双清、电商进口放在二期扩展。

## 2. 一期建议为何分批做

建议分批做，不建议一期把全部进口模式一次性打完。

原因：

1. 海运场景已有较完整 Excel 样本，最容易还原现有财务口径。
2. 完税凭证、GAS COSTS、提单、费用账单等海运单据结构相对稳定，适合先做 AI 解析模板。
3. 先打通“暂估 -> 实际补差 -> ERP 批次成本更新”的主链路，价值最大。
4. 双清、空运、快递的收费结构和合规要求差异很大，过早纳入会显著抬高复杂度。

建议版本节奏：

1. V1：墨西哥海运，人工复核后回写 ERP。
2. V2：加入空运/快递，完善报价解析与运输规则。
3. V3：加入双清、电商进口、规则推荐、自动校验。

## 3. 现有 Excel 核算逻辑拆解

### 3.1 样本定位

本次重点分析文件 [墨西哥进口物料综合成本核算.xlsx](</C:/Users/lin/OneDrive/Desktop/墨西哥进口物料综合成本核算.xlsx>) 中工作表 `2026年YUEWEI` 的第 `79-100` 行。

该区间是一票海运柜的物料明细块，具有以下特征：

1. 报关单号：`26 16 1681 6000151`
2. 中国到墨西哥运单号：`HPCU5155607`
3. 运输方式：`海运`
4. 多个共享字段在这 22 行内做了合并单元格，说明它们属于同一柜/同一票物流：
   - `I79:I100` 报关单号
   - `J79:J100` 运单号
   - `K79:K100` 中国运输及相关杂费 RMB
   - `L79:L100` 中国运输及相关杂费折合 MXN
   - `M79:M100` 中国海运 USD
   - `AR79:AR100` 墨西哥内陆运输费 MXN
   - `AS79:AS100` 墨西哥杂费 MXN
   - `AT79:AT100` 墨西哥内陆运输+杂费 RMB
   - `AU79:AU100` 中国到墨西哥运费 RMB

### 3.2 现有表的核心思路

这段 Excel 不是简单地把所有费用平均分，而是拆成两套分摊池：

1. 货值分摊池：用于清关税费、港杂费、货代服务费等。
2. 重量分摊池：用于中国到墨西哥的运输费用分摊。

最后再将采购货值、税费、运输费、内陆费等汇总成 SKU 级综合成本。

### 3.3 关键字段与含义

1. `C` 单价：部分物料直接填 RMB，部分通过汇率从 USD 折算成人民币。
2. `E` 总货值：`单价 * 数量`
3. `T` 分摊比例（货值比）：当前物料总货值 / 本柜全部物料总货值
4. `AW` 分摊比例（重量比）：当前物料毛重 / 本柜全部物料毛重
5. `AO` 墨西哥清关费用 MXN：税费和杂费的小计
6. `AP` 墨西哥清关费用 RMB：`AO / 2.6`
7. `AX` 中国到墨西哥运输费用分摊 RMB：`总运费 * 重量占比`
8. `BB` 综合成本 RMB：采购货值 + 各类分摊费用
9. `BC` 综合物品单价 RMB：`综合成本 / 数量`

### 3.4 79-100 行的计算步骤

#### 第一步：计算采购货值

1. `E = C * D`
2. 示例：
   - `E79 = C79 * D79`
   - `C79 = 2 / 0.1393`
   - 说明第 79 行单价原始口径是美元，先按 `0.1393` 做汇率转换成 RMB

#### 第二步：按货值计算分摊比例

1. `T = E / SUM(E79:E100)`
2. 作用：用于清关税费及多数港杂费的分摊

示例：

1. `T79 = E79 / SUM(E79:E100)`
2. `T80 = E80 / SUM(E79:E100)`

#### 第三步：计算税费类费用

税费部分由两类组成：

1. 逐行直接录入的税费：
   - `Q` IGI 关税税额
   - `S` IVA 增值税税额
2. 按货值比二次分摊的固定费用：
   - `U = 5532 * T`，DTA
   - `V = 330 * T`，PRV
   - `W = 53 * T`，PRV 的 IVA

合计：

1. `X = Q + S + U + V + W`

#### 第四步：计算清关杂费

多个墨西哥清关杂费字段都按货值比分摊，例如：

1. `Z = 10438.6 * T`，码头操作费
2. `AA = 206.24 * T`，码头作业费
3. `AD = 1500 * T`，货代服务费
4. `AF = 2668 * T`，海关认证费
5. `AM = 5800 * T`，还箱费

本柜中 `Y、AB、AC、AE、AG、AH、AI、AJ、AK、AL、AN` 多数为空，但从表结构上看，也预留了其他清关费用项。

小计：

1. `AO = SUM(X:AN)`，得到墨西哥清关费用 MXN
2. `AP = AO / 2.6`，换算成 RMB
3. `AQ = AP * 0.1393`，换算成 USD

#### 第五步：计算中国到墨西哥运费分摊

这里不是按货值，而是按重量做分摊。

1. `AW = AV / SUM(AV79:AV100)`，`AV` 为毛重 KG
2. `AX = AU$79 * AW`，将总国际运输费 RMB 按重量比分摊
3. `AY = AX * 2.6`，换算成 MXN

说明：

1. `AU79` 是本柜的中国到墨西哥总运费 RMB。
2. 当前样本中 `AU79 = 13976.3`。

#### 第六步：计算综合成本

当前表中最终成本使用的是：

1. `BB = E + K + AP + AX + AT`
2. `BC = BB / D`

字段含义：

1. `E`：采购货值
2. `K`：中国运输及相关杂费 RMB
3. `AP`：墨西哥清关费用 RMB
4. `AX`：中国到墨西哥运输费用分摊 RMB
5. `AT`：墨西哥内陆运输+杂费 RMB

### 3.5 从样本表还原出的算法结论

按业务语义理解，这 79-100 行的目标算法可以抽象成：

`SKU综合成本 = 采购货值 + 中国段费用分摊 + 国际运输费用分摊 + 清关税费分摊 + 墨西哥本地费用分摊`

其中：

1. 清关税费、港杂费主要按货值比分摊。
2. 中国到墨西哥运输费主要按重量比分摊。
3. 汇率在当前 Excel 中是硬编码的。
4. 费用常量在当前 Excel 中是硬编码的。

### 3.6 当前 Excel 口径里的疑点和开发注意事项

这是本次分析里最重要的技术提醒。

从公式和缓存结果看，共享费用字段虽然在视觉上合并到了 `79-100` 行，但 Excel 实际只在首行存值，因此会出现以下现象：

1. `K79:K100` 是合并单元格，但 `BB80 = E80 + K80 + AP80 + AX80 + AT80` 中的 `K80` 实际为空。
2. `AT79:AT100` 是合并单元格，但 `BB80` 里的 `AT80` 实际也为空。
3. `AS79:AS100`、`L79:L100` 也是同样问题，所以 `AZ80:AZ100` 未包含这两项共享费用。

结果上表现为：

1. 第 79 行吸收了整票的 `中国杂费`、`墨西哥内陆运输费`、`墨西哥杂费`。
2. 第 80-100 行没有分到这些共享费用。

这有两种可能：

1. 这是当前 Excel 的既有口径，财务就是这么手工处理的。
2. 这是模板设计问题，视觉上合并了，但公式没有真正做共享费用分摊。

因此开发时不要直接“照着单元格公式抄代码”，而应先跟财务确认真实业务口径。

建议以业务口径为准，按系统算法重构为：

1. `中国杂费池`
2. `国际运输费池`
3. `墨西哥清关税费池`
4. `墨西哥本地内陆费池`
5. `墨西哥杂费池`

然后分别配置分摊规则，而不是依赖 Excel 合并单元格行为。

## 5. 系统总体设计

### 5.1 核心链路

建议系统主链路如下：

1. 从钉钉读取采购支出流程和国际物流流程。
2. 建立“物流批次/柜号 -> 采购单 -> SKU”的关联关系。
3. 接收物流附件、清关附件、完税凭证、Excel 样本等文件。
4. 通过 AI 解析模块抽取关键字段。
5. 生成费用池并按规则分摊。
6. 财务复核、修正、确认。
7. 以批次维度回写 ERP 成本。
8. 后续若拿到实际账单，执行补差重算并再次回写。

### 5.2 模块拆分

一期建议拆成 6 个模块。

#### 模块 1：物流批次关联模块

作用：

1. 从钉钉物流审批中获取柜号、物流方式、物流单号、附件、关联采购审批单。
2. 建立一票物流与多个采购单、多 SKU 的映射关系。

输出：

1. `shipment_id`
2. `container_no / logistics_no`
3. `shipping_mode`
4. `purchase_order_ids[]`
5. `sku_items[]`

#### 模块 2：文件解析模块

这是你补充提到的重点模块，也是一期开发必须包含的能力。

输入文件类型：

1. PDF
2. Excel
3. 图片
4. 扫描件
5. 提单、装箱单、发票、完税凭证、费用清单、报价单

处理方式：

1. 先做文件类型识别。
2. 再按模板进入对应解析器。
3. 非结构化内容用 OCR + 大模型抽取字段。
4. 结构化 Excel/PDF 优先走规则解析，降低幻觉风险。

建议抽取字段：

1. 柜号/运单号
2. 报关单号
3. 提单号
4. SKU/物料编码
5. 品名中英文字段
6. HS Code
7. 申报货值
8. 币种
9. 关税税率/税额
10. IVA 税率/税额
11. DTA / PRV / 码头费 / 货代费 / 仓储费 / 还箱费等费用项
12. 内陆运输费
13. 清关完成日期
14. 供应商
15. 汇率字段

输出：

1. 标准化费用明细
2. 标准化货物明细
3. 字段置信度
4. 原文定位信息

#### 模块 3：费用池与规则引擎

建议不要把 Excel 公式直接固化成一坨逻辑，而是拆成规则引擎。

费用池建议分为：

1. 中国段杂费池
2. 国际运输费池
3. 墨西哥清关税费池
4. 墨西哥港杂费池
5. 墨西哥内陆运输费池
6. 其他杂费池

每个费用池需支持配置分摊规则：

1. 按货值
2. 按重量
3. 按体积
4. 按数量
5. 按指定比例

示例：

1. 清关税费：默认按货值
2. 海运费：默认按重量或体积
3. 双清费用：后续可能按重量或体积
4. 特定品类：允许财务人工覆盖规则

#### 模块 4：暂估与补差模块

因为业务已明确支持“先暂估、后补差”，所以系统必须支持成本版本管理。

建议分为两类版本：

1. `estimated` 暂估版本
2. `actual` 实际版本

流程：

1. 货在途或清关未完结时，用报价、预估费用生成暂估成本。
2. 清关完成、代理账单和完税凭证齐全后，生成实际成本。
3. 若暂估与实际有差额，形成补差记录。
4. 补差结果按批次回写 ERP。

#### 模块 5：人工复核与痕迹管理模块

因为财务要对数据，所以必须允许改，但必须留痕。

建议记录：

1. 修改前值
2. 修改后值
3. 修改字段
4. 修改原因
5. 修改人
6. 修改时间
7. 原始文件来源

复核节点建议：

1. 文件解析后复核
2. 分摊规则确认后复核
3. ERP 回写前最终复核

#### 模块 6：ERP 回写模块

已知 ERP 支持批次成本和 FIFO，因此一期可直接落批次成本回写。

回写建议内容：

1. 批次号
2. SKU
3. 入库数量
4. 综合成本单价
5. 综合成本总额
6. 成本版本：暂估/实际
7. 差额调整金额
8. 来源物流批次号
9. 回写时间

## 7. 算法落地建议

### 7.1 不建议直接复制 Excel 的地方

以下内容不建议在系统中硬编码复刻：

1. 汇率 `0.1393`
2. 汇率 `2.6`
3. 固定费用常量 `5532 / 330 / 53 / 10438.6 / 206.24 / 1500 / 2668 / 5800`
4. 合并单元格带来的“首行吃费用”行为

这些应全部改造成：

1. 可配置费项
2. 可配置汇率来源
3. 可配置分摊规则
4. 独立的费用池记录

### 7.2 推荐的系统算法

建议系统算法顺序如下：

1. 读取采购明细，生成 `SKU 基础货值`
2. 汇总同一票物流的全部费用项
3. 按费用项类型选择分摊规则
4. 计算每个 SKU 的货值占比、重量占比、体积占比
5. 对每个费用池执行分摊
6. 汇总到 SKU 级成本
7. 生成本次批次的暂估或实际成本版本
8. 财务确认后回写 ERP

### 7.3 可直接复刻的公式抽象

1. `goods_value = unit_price_rmb * qty`
2. `value_ratio = goods_value / sum(goods_value)`
3. `weight_ratio = gross_weight / sum(gross_weight)`
4. `allocated_fee = fee_pool_amount * selected_ratio`
5. `sku_total_cost = goods_value + sum(allocated_fee)`
6. `sku_unit_cost = sku_total_cost / qty`

## 10. 建议结论

从这次 79-100 行样本看，财务当前已经有可复用的业务口径，但它散落在：

1. Excel 公式
2. 合并单元格
3. 人工录入费用
4. 钉钉物流流程附件
5. 后补的清关单据

所以一期最正确的做法不是“把 Excel 搬进系统界面”，而是：

1. 把物流批次、采购单、SKU、费用池、附件解析这几层真正建模出来。
2. 把 Excel 中的货值分摊、重量分摊规则沉淀为规则引擎。
3. 把 AI 文件解析做成独立模块，为后续完税凭证自动识别打基础。
4. 先支持海运暂估与补差。
