# OA 国际物流单与当前系统字段对比说明

更新时间：2026-07-14

本说明基于以下两个口径整理：

1. OA 文件：`国际物流Logística+Internacional-20260708110155.xlsx`
2. 系统一期主表：按 Excel `A ~ BE` 顺序展示的海运成本核算总表

## 2. 总体结论

一句话结论：

`OA 国际物流单适合作为“导入入口 + 审批追溯入口”，但不足以单独支撑最终综合成本核算结果。`

原因如下：

1. OA 单可以提供审批信息、物流信息、基础物料信息，适合先生成批次和基础物料行。
2. 但最终综合成本还依赖钉钉 OA `采购支出` 里的进购单价、钉钉附件装箱单中的实际发货数量/重量/体积、报关信息、完税凭证、清关费用、墨西哥段物流费用等关键数据，这些并不完整存在于国际物流 OA 表单中。
3. 因此后续仍需要结合采购支出 OA、装箱单附件解析、报关资料、完税凭证、清关账单、物流账单共同完成成本核算。

## 3. 本次对比范围

### 3.1 OA 国际物流单实际结构

本次核对的 OA 文件包含 `3` 个 sheet，结构一致：

1. `202607031702000470`
2. `202606101808000471`
3. `202606041550000262`

每个 sheet 当前实际业务字段约 `46` 列，主要包含：

1. 审批追溯字段
2. 项目字段
3. 物料与货物信息字段
4. 物流方式与报价字段
5. 时间节点字段
6. 附件与备注字段

### 3.2 当前系统字段范围

当前系统一期主表字段按 Excel `A ~ BE` 展示，共 `57` 个字段，包含：

1. 基础物料字段
2. 报关与运单字段
3. 中国段费用字段

5. 清关费用明细字段
6. 墨西哥段费用字段

## 4. OA 可以直接支撑的内容

以下内容可以直接或基本直接支撑系统首轮导入：

### 4.1 可直接映射字段

1. `物料编码 Código de material` -> 系统 `A 物料编码`
2. `物料名称（中文）Nombre del material (chino)` -> 系统 `B 产品名称`
3. `数量 Cantidad` -> 系统 `D 数量（首轮导入值，后续需与装箱单校验）`

### 4.2 可直接保留的审批追溯信息

以下字段非常适合作为批次头的追溯信息保留：

1. 数据id
2. 审批编号
3. 标题
4. 审批状态
5. 审批结果
6. 发起时间
7. 完成时间
8. 发起人工号
9. 发起人 UserID
10. 发起人姓名
11. 发起人部门
12. 历史审批人姓名
13. 审批记录
14. 当前处理人姓名

这部分信息虽然不直接参与成本计算，但非常适合支撑：

1. 批次来源追溯
2. 钉钉原单跳转
3. 审批过程留痕
4. 问题回查

### 4.3 已从业务补充确认的其它数据来源

这次和同事确认后，可以进一步明确：

1. `进购单价` 不来自国际物流 OA，而来自钉钉 OA `采购支出` 审批单。
2. `发货数量`、`毛重`、`体积` 的最终业务口径不应直接取 OA 表单字段，而应来自钉钉附件中的实际装箱单。
3. `重量 / 体积` 当前业务里基本都存在人工修正，因此系统不能只保留最终值，必须支持修改留痕。

## 5. OA 可以提供，但需要系统做转换的内容

以下字段不是不能用，而是不能直接原样落到主表，需要系统做归一化、拆分或规则转换：

### 5.1 基础业务字段

1. `项目 proyecto`  
   需统一映射到系统 `BD 项目归集`，避免中西文混用。

2. `物料类别 TIPO`  
   需建立 `TIPO -> 大类分类` 规则后，再落到系统 `H 大类分类`。

3. `物流方式 Camino Envío`  
   需统一归一为系统枚举：`海运 / 空运 / 快递`。  
   一期仅保留海运。

4. `柜号/单号 Número DE Logística`  
   需结合业务场景判断是海运提单号、柜号还是其他运单号，再落到系统 `J 中国到墨西哥运单号`。

### 5.2 物流与费用字段

1. `物流费用`
2. `币种 Moneda`
3. `物流报价 Cotización de logística`

这三类字段虽然有价值，但不能直接生成系统里的：

1. `K 中国运输及相关杂费 RMB`
2. `L 中国运输及相关杂费 折合 MXN`
3. `M 中国海运 USD`
4. `AU 中国到墨西哥运费 RMB`

原因是 OA 里更多是总费用、文本报价或单一金额，系统核算需要的是按费用口径拆分后的结构化数据。

### 5.3 时间与补充信息字段

以下字段建议保留到批次头或扩展信息中，不直接进主成本表：

1. `预计发货日期 Fecha de Pre-entrega`
2. `实际发货时间 Fecha de Entrega Real`
3. `预计到港日期 ETA A PUERTA`
4. `目标地区 Países destinatarios`
5. `收件人信息 Información del destinatario`
6. `关联审批单 Asociar órdenes de compra.`
7. `备注 otro`
8. `附件信息 / 评论附件汇总 / 所有附件汇总`

## 6. OA 当前无法单独提供的关键字段

这是本次最核心的结论：  
系统最终核算所需的很多关键字段，OA 国际物流单本身并没有。

### 6.1 采购与货值类

1. `C 单价`
2. `E 总货值`

这两项通常需要钉钉 OA `采购支出` 审批单补齐；其中单价目前已从业务确认在采购支出流程上有原始来源。

### 6.2 实际发货与物理属性类

1. `D 数量` 的最终发货口径
2. `AV 毛重 KG`
3. `体积 m3`
4. `体积重 / 计费重`

这几项不能只依赖 OA。当前业务已确认，它们应来自钉钉附件中的实际装箱单，且经常需要人工修正。

### 6.3 报关基础类

1. `F 海关进口名称`
2. `G 海关分类编码`
3. `I 报关单号`

这三项需要来自报关资料、物料主数据、清关文件或人工确认。

### 6.4 中国段费用拆分类

1. `K 中国运输及相关杂费 RMB`
2. `L 中国运输及相关杂费 折合 MXN`
3. `M 中国海运 USD`

OA 目前没有稳定拆好的结构化字段。

### 6.5 税率税额类

1. `N C.C税率`
2. `O C.C（反倾销附加税）`
3. `P IGI关税税率`
4. `Q IGI关税税额`
5. `R IVA增值税税率`
6. `S IVA增值税税额`

这些都需要报关单、完税凭证或关务录入。

### 6.6 清关费用明细类

系统主表中的 `U ~ AN`，例如：

1. DTA
2. PRV
3. REVALIDACION
4. MANIOBRAS
5. MUELLAJE
6. ALMACENAJES
7. HONORARIOS
8. 还箱费、拖运费、集装箱清洁等

OA 单中均无完整的结构化明细。

### 6.7 墨西哥段费用类

系统主表中的：

1. `AO ~ AQ` 墨西哥清关费用汇总
2. `AR ~ AT` 墨西哥内陆运输与杂费
3. `AU` 中国到墨西哥运费汇总

也都需要后续补充账单或人工录入。

## 7. 系统自动计算字段

系统中还有一类字段本身就不应该由 OA 提供，而应由系统在基础数据补齐后自动生成：

1. `T 分摊比例（货值比）`
2. `AW 分摊比例（重量比）`
3. `AX 中国到墨西哥运输费用分摊 RMB`
4. `AY 中国到墨西哥运输费用分摊 MXN`
5. `AZ 中国到墨西哥运输+清关+杂费 MXN`
6. `BA 分摊运输+物流+杂费到产品的价格 MXN`
7. `BB 综合成本 RMB`
8. `BC 综合物品单价 RMB`

也就是说，即使 OA 把基础字段全部导进来，最终结果仍需要系统重算才能产出。

## 8. 对当前系统建设的意义

基于这次对比，可以明确当前模块的建设方向：

### 8.1 OA 国际物流单适合作为

1. 批次创建入口
2. 审批追溯入口
3. 基础物料行导入入口
4. 钉钉原单跳转入口

### 8.2 OA 国际物流单不适合作为

1. 最终综合成本表唯一来源
2. 税费与清关费用唯一来源
3. 采购货值唯一来源

## 9. 建议的落地方式

建议采用“多来源汇总、系统自动试算”的方式落地：

1. 先用 `国际物流 OA` 生成批次头和基础物料行。
2. 再从 `采购支出 OA` 补充采购单价、采购币种、总货值。
3. 再解析 `钉钉附件装箱单`，补充实际发货数量、毛重、体积，并允许人工修正且保留痕迹。
4. 再从 `报关单 / 完税凭证 / 清关账单 / 物流账单` 补税费、清关费、海运费和墨西哥段费用。
5. 最后由系统按既定分摊规则自动生成综合成本与综合单价。
