# Demo 原型说明：海外采购综合成本核算模块 V1.0

更新时间：2026-07-08

## 1. 文档目标

本文档用于说明当前 `TEST独立版` 前端原型已经实现了什么、数据来源是什么、哪些能力只是演示、哪些能力还没有进入 ERP 正式开发。

适用对象：

1. 经理
2. 产品
3. 前端/后端开发
4. 后续 ERP 接入同事

## 3. 当前 Demo 的定位

这套 Demo 不是 ERP 正式前端，也不是最终交付代码。

它当前的定位是：

1. 用来还原 Excel 成本总表的展示方式
2. 用来验证字段结构和交互是否符合财务使用习惯
3. 用来演示“批次 -> 报关/运单 -> SKU 明细”的层级关系
4. 用来给后续 Frappe 正式开发提供页面和字段参考

一句话概括：

`它是业务原型，不是正式 ERP 模块。`

---

## 4. 当前 Demo 已实现内容

## 4.1 页面布局

当前页面已经具备后台操作界面的基本骨架：

1. 左侧侧边栏
   - 品牌区
   - 一期范围提示
   - 待确认口径提示
2. 右侧主工作区
   - 批次 / 报关 / 运单层级列表
   - 查询筛选栏
   - 明细大表
   - 修改记录
   - 差异追踪

## 4.2 主体交互

当前已经实现的核心交互包括：

1. 父级行 `+ / -` 展开收起
2. 多个报关/运单块独立展开，不互相影响
3. 父级展示汇总信息：
   - 报关单号
   - 运单号
   - SKU 数
   - 中国杂费 RMB
   - 折合 MXN
   - 中国海运 USD
   - 采购货值
4. 子级展示 SKU 物料明细
5. 查询按钮与重置按钮
6. 添加报关运单按钮
7. 导入按钮、文件解析按钮、钉钉订单入口按钮
8. 底部修改记录和差异追踪展示

## 4.3 数据展示能力

当前 Demo 已按 Excel 列顺序展示核心明细字段，重点覆盖：

1. `A ~ BE` 字段结构
2. 产品名称、单价、数量、总货值
3. 海关进口名称、海关分类编码、大类
4. 报关单号、运单号
5. 中国段费用
6. 税率税额
7. 清关费用明细
8. 墨西哥段费用
9. 重量分摊
10. 综合成本结果

## 4.4 可编辑能力

当前 Demo 中多数业务字段已经支持前端直接编辑，目的是模拟财务人工修正场景。

已支持的编辑方向包括：

1. 父级块字段编辑
2. 子级 SKU 字段编辑
3. 费用类字段编辑
4. 查询字段输入

但要注意：

这些编辑目前是前端内存态编辑，不是 ERP 持久化保存。

## 5. 当前 Demo 数据来源

## 5.1 默认演示数据

`app-v2.js` 内部保留了两票默认海运演示块：

1. `HPCU5155607`
2. `PCIU1950292`

它们用于在没有导入数据时快速展示页面效果。

## 5.2 Excel 导入后的主数据源

当前 Demo 更重要的数据源是：

`excel-imported-blocks.js`

这个文件里挂载了：

1. `window.EXCEL_IMPORTED_META`
2. `window.EXCEL_IMPORTED_BLOCKS`

当前前端会优先读取其中的数据。

## 5.3 当前默认取数规则

`app-v2.js` 中的 `getInitialTestBatchBlocks()` 已经做了偏好筛选：

1. 优先取 `sourceSheet === "2026年YUEWEI"`
2. 且 `transportMode` 包含 `海运`

因此现阶段 Demo 主要服务于：

`2026年YUEWEI + 海运`

这个一期范围。

## 6. 当前 Demo 已包含的业务口径

## 6.1 批次层级口径

当前原型已经把数据从单纯大表拆成了更贴近业务使用的层级：

1. 一个批次块对应一组报关单号 / 运单号
2. 一个批次块下面挂多个 SKU 物料明细
3. 父级汇总信息与子级明细联动展示

## 6.2 前端派生计算口径

当前前端已经内置一组简化的派生计算逻辑，主要用于演示：

1. `goodsRatio`
2. `freightAllocRmb`
3. `freightAllocMxn`
4. `totalLogisticsMxn`
5. `allocPriceMxn`
6. `totalCostRmb`
7. `totalUnitRmb`

这组逻辑的意义是：

1. 演示重算后页面会显示哪些结果
2. 帮助确认前端字段是否齐全
3. 为后端正式重算接口预留结果展示位

但要注意：

`它不是最终财务定版算法，只是 Demo 级 MVP 口径。`

---

## 7. 当前 Demo 还没实现的内容

## 7.1 没有正式后端

当前 Demo 主要还是静态 HTML + JS 原型，没有真正对接：

1. Frappe DocType
2. MariaDB
3. ERP 登录权限
4. 持久化保存

## 7.2 没有真正的版本管理

页面虽然有暂估版 / 实际版这类业务概念，但目前还没有真正落地：

1. 版本复制
2. 版本切换
3. 版本锁定
4. 版本差异持久化

## 7.3 没有真实留痕

底部修改记录目前是演示列表，不是来自真实数据库日志。

正式版需要接入：

1. 修改前后值
2. 操作人
3. 操作时间
4. 重算快照

## 7.4 没有真实附件解析

页面上已经有：

1. 文件解析按钮
2. Excel 导入按钮

但目前仍属于前端交互入口，未真正打通：

1. OCR / AI 识别
2. 完税凭证字段提取
3. 解析结果回填

## 7.5 没有 ERP 回写

当前 Demo 还没有接入：

1. 采购单
2. 采购收货
3. 供应商
4. 批次成本回写
5. FIFO 关联

---

## 8. 当前 Demo 的价值

虽然它不是正式 ERP 模块，但当前这版原型已经有很高价值：

1. 帮助确认“整表直展示”方向成立
2. 帮助确认字段顺序、筛选条件、层级关系
3. 帮助确认报关单 / 运单 / SKU 的展示方式
4. 帮助开发理解最终页面长什么样
5. 为 Frappe 正式开发提供字段和交互蓝本

---

## 9. 当前 Demo 与 ERP 正式版的关系

推荐理解为：

1. Demo 决定前端交互和字段展示方式
2. Frappe 设计文档决定正式技术落地方式
3. 后端重算和版本管理以后端为准
4. ERP 正式版不直接复制当前 HTML，而是复用其业务结构

---

## 10. 后续如何从 Demo 走向正式版

建议顺序如下：

1. 先保留当前 Demo 作为业务原型参考
2. 在 ERP 中按 `Frappe + MariaDB` 建正式 DocType
3. 先打通导入、查询、版本、重算接口
4. 再用 ERP Page / Vue 页面重做正式前端
5. 最后补附件解析、差异对比、ERP 回写

---

## 11. 当前结论

当前 `TEST独立版` 已经不是“空白草图”，而是一套可以支撑正式开发讨论的业务原型。

它已经明确了：

1. 一期只做海运
2. 数据主来源是 `2026年YUEWEI`
3. 页面核心是“批次层级 + 整表字段 + 查询筛选 + 修改记录 + 差异追踪”
4. 后续正式开发应迁移到 `Frappe custom app` 中实现
