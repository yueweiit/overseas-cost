# 字段口径待确认清单（对外沟通版）V1.0

更新时间：2026-07-15

## 1. 文件用途

本文用于向产品、财务、物流、关务、主数据/ERP 相关人员确认海外采购综合成本核算模块一期中仍不够清晰的字段口径。

当前模块已进入 Frappe / ERPNext 本地开发环境，基础 DocType、测试批次和主页面已经跑通。下一阶段要继续推进 Excel 导入、成本计算、编辑保存、重算和留痕。因此以下字段口径需要尽快确认，避免后续计算服务和数据模型返工。

参考资料：

1. `08_OA国际物流单与系统字段对比_v1.0.md`
2. `09_OA直拉字段与待确认字段清单_v1.0.md`
3. `10_采购支出OA与装箱单附件来源验证_v1.0.md`

## 2. 总体判断

国际物流 OA 适合作为“批次入口 + 审批追溯 + 基础物料清单来源”，但不能单独支撑最终综合成本核算。

最终综合成本还需要叠加：

1. 采购支出 OA：补采购单价、采购币种、总货值、采购原单追溯。
2. 钉钉附件装箱单 / Packing List：补实际发货数量、毛重、体积、体积重、计费重。
3. 报关资料 / 完税凭证 / 清关账单 / 物流账单：补报关、税费、清关费用、墨西哥段费用。
4. 系统规则层：计算分摊比例、综合成本、综合单价、暂估版和实际版差异。

## 5. 建议优先确认的 10 个问题

1. 采购支出 OA 里，采购单价和采购币种具体取哪个字段作为系统正式口径？
2. 总货值直接取采购支出 OA 的总金额，还是系统按 `单价 * 数量` 重算？
3. 同一票国际物流如果关联多张采购支出 OA，系统按什么规则匹配到 SKU 明细？
4. 数量是否区分采购数量、OA 数量和实际发货数量？最终核算用哪个？
5. 毛重、体积、体积重、计费重是否以装箱单解析结果为最终口径？
6. 装箱单解析后，是直接覆盖现有数量/重量/体积，还是写入待确认字段？
7. 海关进口名称和 HS Code 最终以物料主数据、报关资料还是完税资料为准？
8. 报关单号在暂估版是否允许为空？后续补录时按整票还是 SKU 行关联？
9. 中国运输杂费、中国海运 USD、中国到墨西哥运费 RMB 中，哪个是主口径，哪个只是换算结果？
10. 一期费用分摊中，哪些费用按货值，哪些按重量，哪些按体积？

## 7. 当前开发建议

在以上 P0 问题未完全确认前，开发可以继续推进以下低返工事项：

1. 保留并完善当前 Frappe 页面和测试批次。
2. 稳定 Excel 导入，先支持 `2026Yuewei 海运数据`。
3. 对已明确字段继续落库：物料编码、物料名称、数量、单价、币种、货值、报关/运单基础字段。
4. 对待确认字段先预留结构，不把复杂计算规则写死。
5. 计算服务先做可配置规则版本，不直接把分摊规则硬编码到前端。
6. 钉钉 OA 深度接入放在字段口径和计算闭环之后推进。

一句话结论：

当前最大风险不是字段建不出来，而是字段口径未统一。建议尽快组织产品、财务、物流、关务做一次 P0 字段确认会，再继续深入计算服务和 OA 自动接入。
